1 · „Job speichern“ (Safari)

Speichert die komplette Stellenbeschreibung, Firma, Stelle, Ort und Link der Seite, die du in Safari offen hast. Funktioniert auch bei LinkedIn, wenn du in Safari eingeloggt bist.

  1. App Kurzbefehle öffnen → oben rechts +.
  2. Oben auf den Namen tippen → Umbenennen → Job speichern.
  3. Unten auf ⓘ → Im Share-Sheet anzeigen einschalten → Fertig.
    Oben steht jetzt „Empfängt Alle aus Share-Sheet“: auf Alle tippen und nur Safari-Webseiten angehakt lassen.
  4. Unten in der Suche JavaScript eingeben → JavaScript auf Webseite ausführen antippen.
    Den Beispieltext in der Aktion komplett löschen und diesen Code einfügen:
    job-speichern.js (ca. 60 Zeilen)
  5. Suche: URL abrufen → Inhalte von URL abrufen.
    • Auf URL tippen → App-Link einfügen.
    • Auf den kleinen Pfeil > tippen → Methode POST → Anfragetext JSON.
    • 3× Neues Feld hinzufügen → Text:
    SchlüsselWert
    fn
    apiSavePosting
    keydein Schlüssel (siehe oben)
    dataüber der Tastatur die Variable JavaScript-Ergebnis antippen
  6. Suche: Wörterbuchwert → Wörterbuchwert abrufen → bei „Schlüssel“ result eintragen. Als Eingabe muss Inhalte von URL stehen.
  7. Noch einmal Wörterbuchwert abrufen → Schlüssel message. Eingabe: Wörterbuchwert.
  8. Weiter mit Abschnitt 3 · Nachfrage „ersetzen?“, dann oben rechts Fertig.

Test: In Safari eine Stellenanzeige öffnen → Teilen → ganz nach unten → Job speichern. Beim ersten Mal fragt das iPhone, ob der Kurzbefehl auf die Seite zugreifen darf: Erlauben.

2 · „Job-Link speichern“ (LinkedIn-App & andere Apps)

Aus Apps bekommt ein Kurzbefehl nur den Link. Der Job wird mit Link angelegt; die Beschreibung holt der Job-Tracker selbst, wenn die Seite das erlaubt. Klappt das nicht, steht in der App „Anzeige noch nicht gespeichert“, und du sicherst sie später mit Kurzbefehl 1 in Safari.

  1. In Kurzbefehle → + → umbenennen in Job-Link speichern.
  2. ⓘ → Im Share-Sheet anzeigen einschalten. Bei „Empfängt“ nur URLs und Text anhaken.
  3. Inhalte von URL abrufen hinzufügen: URL = App-Link, Methode POST, Anfragetext JSON, 3× Neues Feld → Text:
    SchlüsselWert
    fn
    apiSaveShared
    keydein Schlüssel
    sharedVariable Kurzbefehleingabe
  4. Wie oben: 2× Wörterbuchwert abrufen (result, dann message), danach Abschnitt 3.
  5. Fertig.

Test in der LinkedIn-App: Job öffnen → Teilen (Pfeil) → Teilen über … bzw. Mehr → Job-Link speichern.

Tipp: Fehlt „Job speichern“ im Teilen-Menü (z. B. in der Anzeige, die aus dem Job-Tracker geöffnet wurde), nimm einfach „Job-Link speichern“.

3 · Nachfrage „ersetzen?“ (für beide Kurzbefehle)

Hat ein Job schon eine Anzeige, fragt der Kurzbefehl jetzt, ob die neue sie ersetzen soll. Ohne diese Schritte wird nichts ersetzt, du bekommst dann nur die Frage als Mitteilung. Wenn du die Kurzbefehle schon hast: die alte Aktion Mitteilung anzeigen am Ende löschen und das hier anhängen.

So wählst du eine bestimmte Variable: ins Feld tippen → über der Tastatur Variable auswählen → im Kurzbefehl auf die Aktion tippen, deren Ergebnis du willst.

  1. Wörterbuchwert abrufen → Schlüssel
    confirm
    Als Eingabe Inhalte von URL wählen (die Antwort vom Job-Tracker, nicht „Wörterbuchwert“).
  2. Suche: Wenn → Wenn. Eingabe: das Ergebnis aus Schritt 1 (Wörterbuchwert mit confirm). Bedingung: hat einen beliebigen Wert.
  3. Zwischen Wenn und Sonst einfügen:
    • Hinweis anzeigen → Text: Variable Wörterbuchwert der Aktion mit Schlüssel message. „Abbrechen-Taste anzeigen“ bleibt an.
    • Inhalte von URL abrufen → URL: Variable aus Schritt 1 (confirm). Methode bleibt GET, keine Felder.
    • Mitteilung anzeigen → Text: Inhalte von URL (der eben abgerufenen).
  4. Zwischen Sonst und Ende Wenn: Mitteilung anzeigen → Text: Variable Wörterbuchwert mit Schlüssel message.

Ablauf: Neue Anzeige für einen Job, der schon eine hat → Frage „Durch die neue ersetzen?“ → OK ersetzt sie (Mitteilung „Anzeige ersetzt ✓“), Abbrechen lässt die alte stehen. Die Frage gilt 30 Minuten. Ist der Text gleich, kommt keine Frage.

Etwas klappt nicht?

Die Mitteilung ist leer: Füge hinter Inhalte von URL abrufen vorübergehend Ergebnis anzeigen ein. Dort steht der Grund, z. B. "error": "Kein Zugriff" (Schlüssel falsch) oder eine Seite von Google (App-Link falsch oder Apps Script nicht neu bereitgestellt).
